# 微信 → 怀恩（方案 A 实施记录）

> 用户 2026-11-03: *"微信连接的就是怀恩。助手是很早之前的事了。"* → 选方案 A。

## 目标

| 通道 | profile | 人格 |
|---|---|---|
| **微信** | `huaien` | 怀恩 —— 话不多，但活要干 |
| **桌面** | `default` | 助手 —— 开发搭档，帮你优化怀恩 |

**共享**：同一个模型、同一套工具、同一个技能库。

## 实施

### 1. 官方机制：`gateway.profile_routes`

`gateway/profile_routing.py` 的匹配规则：

- 条件**合取**（声明了哪个字段就必须全中）
- 特异性加权：`user_id 16 > thread_id 8 > chat_id 4 > guild_id 2`
- `bot_profile` 默认 `None` = default profile 的共享 bot

```yaml
gateway:
  multiplex_profiles: true        # 本来就是 true（不是新开的开关）
  profile_routes:
    - profile: huaien
      platform: weixin
      chat_id: <WECHAT_CHAT_ID>@im.wechat
```

**改配置必须用 `hermes config set`**（agent 不能直接写 `config.yaml`）：
```bash
hermes config set gateway.profile_routes '[{"profile":"huaien","platform":"weixin","chat_id":"..."}]'
```

### 2. 生效证据（gateway 日志）

```
12:35:17  [Weixin] inbound from=<CHANNEL_ID> type=dm media=0
12:35:17  [Weixin] Flushing text batch agent:huaien:weixin:dm:<WECHAT_CHAT_ID>@im.wechat
                                                                    ↑ 目标 profile
```

对比之前：`agent:main:weixin:dm:...`（default）

### 3. 换 profile = 换配对表，要重新批一次

路由到 huaien 之后，用户在微信收到：
```
你的配对码：USVD4X85
hermes -p huaien pairing approve weixin USVD4X85
```
**注意那个 `-p huaien`** —— 不带 profile 参数批不上。

批完两个 profile 都在 Approved 列表里 → 以后来回切不会重复要审批。

```

11:36:36  gateway 已确认停止        ← 精确 PID 确认（RestartOnFailure PT1M 会复活）
11:36:36  starting gateway

11:37:08  wedged sessions: 3 → discard ×3 全部 rc=0
```

**围堵扫描救回了 3 个会话**（包括用户的 `<CHANNEL_ID>_c902a0`）：
被 19:23 那次停机 fence 成 `status='unknown'` 的轮次会**永久堵死那些会话的 FIFO**，
表现是"微信一直正在输入中"而 `integrity_check` 还是 ok。

**不扫围堵，重启就是制造新围堵。**

## 语音链路（同期修好的）

4 层根因，逐层修：

| 层 | 问题 | 修法 |
|---|---|---|
| 1 | `pilk` 没装 → `.silk` 解不了 | 装进 `hermes-agent\_vendor_pilk`（永久目录） |
| 2 | `huggingface.co` 爬墙不通 | `HF_ENDPOINT=hf-mirror.com`（实测 200 / 1.08s） |
| 3 | `stt.language: en` 写死英文 | `hermes config set stt.language zh` |
| 4 | base 模型把 "Hermes" 听成"荷尔蒙斯" | `initial_prompt` 喂专有名词 + `device: cpu` |

```
修之前 (96.7 秒后失败):  'You can now connect to my computer to the hammer...'
修之后 (3.9 秒成功):   '你现在能连接我电脑上那个Hermes 吗?现在是Hermes的后台在跟我理解对话吗?'
```

**为什么要装进永久目录**：`installs/*/environments/*` 里的 lease 环境**会被换掉**
（实测 `a4bd46ce...` 已经不存在了，变成了 `04371c37...` / `c7f5ca6a...`）。
`_vendor_pilk` + vbs 的 PYTHONPATH 不受影响。

## 一个必须记住的教训

**之前报的所有 "ruff 0" 全是假的。**

Hermes 的依赖同步把 pytest / ruff 从**它自己的 venv** 里清掉了，
`python -m ruff` 失败时 stdout 是空、错误在 **stderr**，
而当时的验证代码是：

```python
print(stdout or "All checks passed!")     # ← 工具没跑被打印成了"通过"
```

**修法**：
1. 项目独立 venv `<PROJECT_ROOT>\.venv`（Hermes 的 venv 会被清掉，项目自己的才稳）
2. 验证一律看 **returncode**，不看 stdout 空不空

**代码本身确实没问题**（真跑也是 0 问题）—— 但**不可信的"通过"比失败更危险**。
