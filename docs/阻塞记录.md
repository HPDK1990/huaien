## 2026-10-30 — 看门狗前台探针自匹配, 前台死了也报 alive

**状态**: ✅ 已解决 (根因已定位并修复, 版本 0.1.2)

### 现象

回归看门狗第一次运行时, `python scripts/watchdog.py --status` 报
`gateway: alive` / `frontend: alive`, 但**前台窗口根本不存在**。

独立核查 (绕开看门狗自己的探针):

| 判据 | 结果 |
|---|---|
| `-m huaien` 模块进程 | **0 个** |
| 可见窗口标题含「怀恩」 | **0 个** |
| 旧探针计数 (`-match 'huaien.app'`) | **5** (4 个是探测链自身) |

### 根因

`scripts/watchdog.py` 的 `frontend_alive()` 原来这么写:

```powershell
Get-CimInstance Win32_Process |
  Where-Object { $_.CommandLine -match 'huaien.app' } |
  Measure-Object | ForEach-Object { $_.Count }
```

探测命令**自身的** PowerShell 进程, 命令行里就含 `huaien.app` 这个字符串。
`Where-Object` 于是把它自己也匹配进去 —— 计数恒 >= 1。

**后果**: 前台全死时看门狗永远报 "alive", 于是永远不会执行 `start_frontend()`。
这是一个**静默失效**: 看门狗看起来一直在跑、一直在报绿, 实际上从来没真正看过前台。

### 试过的方法 (三种)

1. **`watchdog.py --once`** —— 失败。它自己也信了坏探针, 报 `frontend=True`,
   直接跳过拉起。日志实测: `单次检查: gateway=True frontend=True`, 无拉起动作。
2. **手工起前台 (`python -m huaien.app`)** —— **成功**。前台起来了, 但坏探针还在,
   下次照样瞎报。
3. **杀掉前台 + 修探针 + 回归验证** —— **成功**。这是根治。

### 修复

探针改成三重过滤, 三条缺一不可:

```powershell
$p = @(Get-CimInstance Win32_Process | Where-Object {
  $_.Name -match '^python(w)?\.exe$' -and          # 1. 只认 python 进程
  $_.CommandLine -match '-m\s+huaien\.app' -and    # 2. 只认模块调用
  $_.CommandLine -notmatch 'Get-CimInstance' });   # 3. 排除探针自身
$p.Count
```

配套新增 `tests/test_watchdog.py` (11 条), 其中一条是**元测试**:
把当年的坏探针拿出来, 断言它会被这套守卫判死 —— 保证回归测试本身不是空转。

测法: 过滤条件单独拆成 `FRONTEND_FILTER_PS` 常量, 单测把它当 PowerShell
scriptblock 喂**假进程**进去, 用真 PowerShell 语义判定 —— 不用在 Python 里
复刻一遍正则 (两边各写各的, 迟早跑偏)。

### 验证 (真实工具输出)

- `watchdog --once` → 成功拉起, 独立探针确认 `-m huaien.app` 进程 2 个 ✅
- 探针改回旧写法后, 新单测 **5 条红** ✅ (确认测试有牙齿)
