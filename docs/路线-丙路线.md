# 路线：丙 —— 怀恩作为独立程序

> 定于 2026-11-12。用户确认："怀恩以后要能自己改自己的代码、自己发版"这个目标是真的。

## 一句话

**怀恩不复制 Hermes、不抢 Hermes 的进程拓扑，只通过命令行和几个约定文件用 Hermes 的能力。**
主 Hermes 升级 = 怀恩免费升级；怀恩自己的代码由怀恩自己改、自己测、自己发版。

## 为什么不是别的路

| 路线 | 做法 | 为什么不要 |
|---|---|---|
| 甲：profile | 怀恩 = 主 Hermes 的一个 profile，共用一个网关进程 | 改不了自己的程序（代码在主仓）；重启网关连累所有会话 |
| 乙：独立 gateway | 给 huaien 装专属网关进程 | 官方已明令废除（见下）；update 会静默折回；**独立进程只是外壳，仍然改不了程序** |
| **丙：独立程序** | 怀恩有自己的 repo、自己的进程、自己的测试与发布链，Hermes 只当能力供应商 | ✅ |

**关键判断**：进程隔离是为"故障隔离"付的代价，自进化需要的是"代码独立"。丙路线里进程独立是自然结果 —— 不用去跟官方抢拓扑。

## 官方硬约束（2026-11 核对源码与文档）

Hermes 官方源码里有一条决定性规则：

```
Multiplex-only (Teknium ruling): exactly one `hermes gateway run` per host,
serving every profile. ... reinstalling per-profile services is no longer a
supported topology.
```

- 一个 host **只允许一个** `hermes gateway run`
- `hermes -p <profile> gateway install --force` 是**受限例外**，不是推荐路径
- `hermes update` 之后会自动跑 `gateway migrate --multiplex --yes` 把拓扑收敛回单网关（确定性、不询问，为的是 headless/cron update 也能收敛）
- 独立服务仍使用**同一份 `hermes-agent` 代码树**和全局插件 —— 独立 ≠ 失去更新

**结论：不跟官方抢进程拓扑。要隔离，走"怀恩是独立程序"这条路。**

## 三个代码边界

| 边界 | 路径 | 谁能改 |
|---|---|---|
| 上游 Hermes | `%LOCALAPPDATA%\AppData\Local\hermes\hermes-agent` | **怀恩禁改**。跟随 `hermes update` |
| 怀恩产品 | `<PROJECT_ROOT>` | **怀恩可改**（自进化发生在这里） |
| 中性公开副本 | `<公开副本目录>` | 只由导出器生成，发布链操作 |

## 怀恩依赖 Hermes 的方式（耦合面）

实测：怀恩对 Hermes 的耦合 **95% 在 CLI + 文件约定层，只有 3 处内部 import**。

| 形式 | 用途 |
|---|---|
| `hermes kanban list/show/swarm/create/link/reclaim` | 任务图、多 agent 编排 |
| `hermes send -f/-t` | 微信/飞书投递 |
| `hermes -p huaien -z` | 调模型 |
| `hermes gateway status/start/stop` | 网关运维 |
| `gateway.lock` / `state/gateway.heartbeat` | 网关生死判据 |
| `state.db` | 会话存储（只读访问） |
| 内部 import（3 处） | 网关 session ticket、FTS 布局 —— 工具性，可选 |

## 契约层：让"吃升级"可验证

**问题**：主 Hermes 升级改了 flag / JSON 结构 / 表结构，怀恩会**静默**坏掉 —— 读到空而不是报错。

**做法**：

- `config/hermes_contract.json` —— 声明怀恩依赖的每一个接口，每条带 `used_by` 指明谁依赖它
- `tests/test_hermes_contract.py` —— 逐条验证，失败时点名依赖方
- 契约测试随 pytest 自动进回归看门狗；另加 2.5 步单独跑，让"上游接口漂移"在 `regression.log` 里一眼可见
- 公开副本没有 Hermes 安装时全部 skip，不误报失败

**效果**：主 Hermes 升级后 → 怀恩跑一遍自己的测试 → 全绿 = 没影响；有红 = 立刻知道哪条约定变了。

## 自进化边界（硬规则）

怀恩**可以**：

1. 改 `<PROJECT_ROOT>` 里的任何代码
2. 跑自己的单测、契约测试、端到端 drill
3. 跑敏感信息审计
4. 生成版本号、CHANGELOG、tag
5. 导出到 `<公开副本目录>`，审计通过后提交/推送

怀恩**不可以**：

1. 改写上游 Hermes 仓库的代码
2. 跳过审计直接发版
3. 携带真实凭据 / 真实渠道 ID / 真实昵称进公开副本
4. 让公开程序默认连到用户的账号、聊天、模型账单或本地状态库

## 自发布链（每次发版必走）

```
改代码 → 单测+契约+drill → 敏感审计 → 版本号/CHANGELOG/tag
      → 导出中性副本 → 副本独立审计 (致命0/提示0)
      → 副本建新 git 历史 → commit → push
```

**失败任一步就停在那一步，不推。**

## 与"进程隔离"的关系

**不做 per-profile 独立网关。** 需要"重启不连累别的会话"时，靠：

- 官方 `hermes gateway restart` 的 planned-stop + drain（不 fence 会话）
- 守护只对**已死**网关动手，绝不替换活网关
- 怀恩自己的进程（前台、报告、看板编排、守护）不寄生在网关进程树里
