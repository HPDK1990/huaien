## 一、完整流程（九步）

```
① 入口（4 个）
      怀恩前台(Tk) ─┐
      微信          ─┤
      飞书          ─┼─▶ ② 路由（profile_routes）
      桌面          ─┘              │
                                    ▼
③ 会话识别  session_key = agent:<profile>:<platform>:<chat>
                                    │
                                    ▼
④ 上下文装载（历史 + 压缩 + 摘要）
                                    │
                                    ▼
⑤ 工具集（platform_toolsets 决定这一轮有哪些工具）
                                    │
                                    ▼
⑥ 执行（agent 循环 + 工具调用 + 记忆读写）
                                    │
                    ┌───────────────┼───────────────┐
                    ▼               ▼               ▼
             ⑦ 记忆            ⑧ 输出          ⑨ 任务拆解
          MEMORY/USER      文字/媒体回各渠道      kanban + delegation
```

### ① 入口 —— 四条路，各走各的

| 入口 | 通路 | 实测证据 |
|---|---|---|
| **怀恩前台**（`<PROJECT_ROOT>`） | `huaien/app.py` → `bridge.py` → `hermes ... --format stream-json --pass-session-id --oneshot [--resume <sid>]` | 逐行解析 stream-json 做打字机效果；状态机 `idle → thinking → typing → idle` |
| **微信** | weixin adapter 长轮询 `ilinkai.weixin.qq.com` | `[Weixin] Connected account=0fcb445b` |
| **飞书** | feishu adapter websocket | `[Feishu] Connected in websocket mode` |
| **桌面** | local platform | `chat=<CHANNEL_ID>_87a316` |

### ② 路由 —— `gateway.profile_routes`

```yaml
gateway:
  multiplex_profiles: true
  profile_routes:
    - profile: huaien          # 微信 → 怀恩
      platform: weixin
      chat_id: <WECHAT_CHAT_ID>@im.wechat
```

**实测生效**：
```
[Weixin] Flushing text batch agent:huaien:weixin:dm:<WECHAT_CHAT_ID>@im.wechat
                                                      ↑ 走的 huaien, 不是 default
```

### ③ 会话识别

`session_key = agent:<profile>:<platform>:<chat_type>:<chat_id>`

| 场景 | 会话粒度 |
|---|---|
| 怀恩前台 | 一个窗口一条会话，靠 `--resume <session_id>` 延续 |
| 微信私聊 | 一个好友一条（`agent:huaien:weixin:dm:<id>`） |
| 桌面 | 一个窗口一条 |

**换 profile = 换配对表**（路由到 huaien 后微信那条好友要重新批一次：
`hermes -p huaien pairing approve weixin <code>`）。

### ④ 上下文装载 —— 历史 ≠ 上下文

```
messages 表:
  active = 1              14290 条   ← 送进模型上下文
  active = 0              36092 条   ← 压缩掉的历史, 完整留着可搜索
  _compressed_summary = 1     54 条   ← 摘要行 (每行一个压缩产物)
  compacted = 1            27874 条
```

压缩参数（`config.yaml`）：
```yaml
compression:
  threshold: 0.5        # 上下文用到 50% 触发
  target_ratio: 0.2     # 压完留 20%
  protect_last_n: 20    # 保护最近 20 条
  protect_first_n: 3    # 保护最早 3 条
```

**"历史"完整存下来供搜索/审计，"上下文"只放摘要 + 最近几轮** —— 这就是业界说的
「历史 ≠ 上下文」，Hermes 用 `messages.active` 这个布尔位实现。

### ⑤ 工具集 —— **这一层决定"能不能拆任务"**

实测 `_get_platform_tools(config, platform)` 的结果：

| 平台 | 工具集 | kanban | stt | video | delegation | terminal |
|---|---|---|---|---|---|---|
| **cli**（桌面 / 怀恩前台） | `hermes-cli` (20) | ✅ | ✅ | ✅ | ✅ | ✅ |
| **weixin** | `hermes-weixin` (18) | ❌ | ❌ | ❌ | ✅ | ✅ |
| **feishu** | `hermes-feishu` (20) | ❌ | ❌ | ❌ | ✅ | ✅ |

**微信/飞书默认工具集里没有 `kanban`** —— 这是 `hermes-weixin` 插件工具集的组成决定的，
不是没装。

### ⑥ 执行

Agent 循环 + 工具调用。怀恩人格的执行契约（`profiles/huaien/SOUL.md`）：

> **用户交代的事，一定要真的做完。**
> - 能做的就动手做，做完再回话。不要只应一声就不动了。
> - 做完了回一句结果就行，不用描述过程。

实测（微信里）：
```
[你] 把电脑上的 E:\...\test_report.txt 发给我
[工具] ls -l → 266 B
[工具] read_file → 5 行内容
[怀恩] 文件在，266 字节，内容是微信文件通道测试报告。发你了。  MEDIA:...
```

### ⑦ 记忆

| 位置 | 内容 |
|---|---|
| `~/.hermes/memories/MEMORY.md` | 跨会话事实（环境、约定、教训） |
| `~/.hermes/memories/USER.md` | 你是谁、你的偏好 |
| `profiles/huaien/memories/` | 前台 profile 自己的记忆 |
| `scripts/sync_memory.py` | 前台 ↔ 后台 **条目级双向补齐**（只补不删、幂等） |

### ⑧ 输出

- **文字** → 各渠道原生发送
- **媒体** → 消息里写 `MEDIA:/绝对路径`，adapter 自动拆成附件
- **微信的两条硬约束**（实测）：
  - **一个附件一条消息**（`item_lists` 逐条发）
  - **iLink 的 sendmessage session 有寿命**：连发约 3 条就废，**退避无效**，
    必须用户再发一条消息才复活

### ⑨ 任务拆解 —— 三条路径

**路径 A：看板（kanban）** —— `hermes kanban` 有 40+ 子命令

| 命令 | 作用 |
|---|---|
| `create` | 建卡（可指定 `--assignee` / `--parent` / `--priority` / `--skill` / `--goal`） |
| `link` / `unlink` | 建依赖边（父→子） |
| `swarm` | 建 Swarm v1 图（并行 workers → verifier → synthesizer） |
| `decompose` | 把 triage 任务**自动拆成子任务图**，按描述路由到专门 profile |
| `specify` | 把 triage 任务细化成具体 spec |
| `claim` / `dispatch` | 认领 / 派单（dispatcher 随 gateway 自动 tick） |
| `complete` / `block` / `request-review` | 流转状态 |

**路径 B：子代理（delegation）** —— `delegate_task` 工具，**所有渠道都有**
（`max_concurrent_children: 5`）。子代理拿自己的上下文干活，回来汇总。

**路径 C：微信里的绕行方案（实测可行）**
微信没有 kanban 工具，但**有 terminal**：
```bash
hermes -p huaien kanban create "标题" --body-file <UTF-8文件> --assignee huaien --json
→ rc=0, 卡号 t_7c84f625
```
**中文标题/正文必须走 UTF-8 文件**（`--body-file`）—— MSYS 直接传中文参数会乱码。

## 二、**任务拆解到底能不能用？—— 分渠道说清楚**

| 渠道 | 直接用 kanban 工具 | 拆任务的实际可行性 |
|---|---|---|
| **怀恩前台 / 桌面** | ✅ 有 | **直接可用**，一句话建卡 |
| **微信** | ❌ 没有 kanban 工具 | ⚠️ **能，但要走命令行**（terminal 工具在，已实测通过） |
| **飞书** | ❌ 没有 kanban 工具 | ⚠️ 同上 |

**看板上现在有 11 张真实卡**，包括一条完整的
`T1 调研现状 → T2 实现脚本 → T3 质量验收` 依赖链（researcher → coder → auditor 三个
profile 分别执行），还有 Swarm 图和 AB probe 卡 —— **拆解机制是真跑过的，不是配置摆设**。
