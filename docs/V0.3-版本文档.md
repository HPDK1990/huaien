# 怀恩 V0.3.0 — 版本文档

> 2026-10-30。这版的目标很明确:
> **让前台真的能干活**, 并且**按用户的真实操作方式**验证它。

---

## 一、这一版做了什么

### 1. 界面重做（用户报"无法输入字、看不真切字"）

| 问题 | 根因 | 修法 |
|---|---|---|
| **中文打不出来** | 输入层是 Canvas + `<Key>` 手工模拟键盘 (`e.char`)。IME 组合时 `e.char` 为空 | 输入框换成**原生 `tk.Text`**（走 Windows IME），手工键盘层彻底删除 |
| 光标位置不准 | 自己按字符宽度估算 | 用控件自带光标，位置由 Tk 自己算 |
| 焦点不在输入框 | `focus_set()` 只在 `run()` 里调 | `__init__` 里就设 + 150ms 后再设 |
| **字看不清** | 字号 15/19/10pt；`FG_FAINT` 对比度 2.37:1；`ACCENT_DIM` 2.79:1 | 字号 17/21/12pt；对比度提到 4.89:1 / 5.33:1 |
| 输入框不长高 | `<<TextChanged>>` 在本机 Tk 8.6.12 **根本不触发** | 改状态比对轮询（45ms 一次） |
| 横线跑偏 | `side="bottom"` 时先 pack 的在更下面 | 容器 frame 统一装横线 + 输入框 |
| 回复被拆成一行几个字 | Tk Canvas 自动换行对中文不可靠 | 自研换行（`tkfont.measure()` 精确测量，中文按字、英文按词） |
| 宽度算成负数 | `winfo_width() or WINDOW_W` —— 未映射时返回 **1**（truthy！） | 显式判 `<= 1` |

### 2. 干活能力（用户最核心的问题）

- **产物协议**：agent 用 `[[FILE:路径]]` / `[[IMG:路径]]` 标注产出，前台剥掉标记、渲染成可双击打开的一行。
- **状态行**：思考时一行灰字（8 秒后才显示"还在想 · N 秒"），不展开成面板。
- **人格改写**（`huaien` profile 的 SOUL.md）：核心一条是**"用户交代的事一定要真的做完"**。
  之前的版本有"长任务先应一声"，结果 agent 应完就躺平 —— 已删。
- **记忆打通**：`scripts/sync_memory.py` 做前后台 profile 的条目级**双向补齐**（只补不删，幂等，带上限感知）。

### 3. 手机端（"能写个手机软件就好了"的可行落地）

`huaien/web.py` —— 同一个怀恩换成网页版：

- 手机连同一 WiFi 打开 → **添加到主屏幕** = 原生 App 体验
- **16 位随机口令**保护（这个接口能指挥 agent 动你的文件，等同电脑权限）
- PWA 三件套齐：manifest / service worker / icon

### 4. 前台真实操作测试器（用户点名要的）

`scripts/gui_drill.py` —— **不调内部函数，只走事件层**：

- 鼠标点击输入框 → 逐字打字 → 按回车 → 等回复
- 断言只看**屏幕上的文字、输入框内容、截图像素**
- 11 个场景，离线（界面交互）+ live（真干活能力）两种模式

## 三、这版发现的真 bug（都是测试逼出来的）

| # | 症状 | 根因 |
|---|---|---|
| 1 | agent 应一声就不干活了 | SOUL.md 的"长任务先应一声" |
| 2 | 记忆写不进去 | `memory.write_approval: true` —— 无人值守模式没人能批准 |
| 3 | 记忆写不进去（第二个原因） | `MEMORY.md 2780 > limit 2200` → 超限后**所有后续写入被拒** |
| 4 | 用户的话会凭空消失 | `bridge.busy` 时 `_on_return` 静默丢弃消息 |
| 5 | Esc 之后还留着上一轮的错误提示 | `reset()` 没清 `_error` / `artifacts` / `_t0` |
| 6 | 屏幕上两个省略号 | reply 区显示 `…`，状态行也显示 `…` |
| 7 | 测试拿到上一轮的回答当这一轮的 | `wait_reply` 只看"非空"，且没等 bridge 空闲 |
| 8 | 测试断言"文件不存在"但文件真写了 | `wait_reply` 把思考中的 `…` 当成回复，提前断言 |

**没有一个是"后台测"能发现的** —— 1、4、5、6 都是跨层时序问题。

## 四、已知限制（诚实记录）

1. **飞书收端未做端到端验证** —— 用户需要在飞书发一条消息确认（通道本身是 connected 的）。
2. **公网可达性无法本地证实** —— STUN 全部超时，本地自测是 hairpin 会低报失败。需要手机流量实测。
3. **微信群聊大概率不通** —— 腾讯 iLink 的限制（只私聊可靠），不是 Hermes 的问题。
4. **图片粘贴不支持**（桌面版）—— Tk 的 Text 粘贴图片要自己读 DIB 转 PNG，没硬凑。Web 版能显示图片。
5. **任务进度只有一行状态字** —— 不做实时看板，这是极简原则的主动取舍。
6. **桌面版和 Web 版各是各的会话线** —— 但走同一个 `huaien` profile，记忆是通的。
