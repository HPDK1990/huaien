## 二、这一轮实测出的 4 个真问题（都已修）

### 1. 快捷指令问模型 = 80 秒起步

手机上点「汇报进度」，怀恩去读 `logs/pwa_run.log`、查端口、**还 spawn 了 2 个子代理**。

根因：「汇报进度」是**纯看板查询**，问模型等于让它自己查一遍。

修法：`board.quick_text()` + `/api/quick/<key>`，直读 SQLite，**不问模型**。

```
progress 14ms | todo 26ms | busy 15ms | live 16ms
浏览器实测点一下 → 530ms 出结果
```

### 2. 会话串了（用户"盯一大堆会话"的病根）

`bridge.py` 无条件 `--resume` 上一个 session。上一轮被 kill 掉的**半截会话**被 resume，
怀恩接着旧任务跑，而不是回答新问题。

修法：一轮没正常跑完（超时 / 异常 / 没收到 `result` 事件）就**清掉 `session_id`**，
下一轮开新会话。

### 3. PWA 端口写死 8765

8765 长期被 ESP32 的 `spectrum_server_v17.py` 占着。
（怀恩在自己的 commit message 里说"改用 8766"，但**代码和启动器都没改**。）

修法：`bind_free_port()` 往后找空端口，并把实际端口 + 口令写进
`logs/pwa_endpoint.txt`（用户和脚本都能直接读）。

### 4. 快捷指令按钮在手机上被截断

375 px 视口下第 4 个按钮「现在有什么活」被切掉。

修法：`flex` 横向滚动 → `grid 1fr 1fr` 2×2 网格。
实测 4 个按钮 `visible` 全 `True`，`scrollWidth == clientWidth` 无溢出。

## 四、三个 worker 人格（本轮重写）

以前 `researcher` / `coder` / `auditor` 全是克隆 default 的**「助手」人格** ——
名字不同，人格一样，等于没分工。现在：

| profile | 职责 | 纪律 |
|---|---|---|
| **researcher** | 查证、摸现状 | 只读；**不碰 secrets/.env/凭据**（无人值守会卡死流水线）；查不到就写"查不到" |
| **coder** | 写代码、跑脚本 | 先读现有代码照风格写；**必须真的跑一次**贴真实输出；不删文件不改配置 |
| **auditor** | 独立核对 | **不复信前一个人的结论**；自己重新查；只出结论不改文件 |

### 踩过的坑：worker 的环境假设会出错

P1 那轮报告里断言"本机 psutil 没装 → 门禁失效"。
主代理用**两个解释器各跑一次** `wait_gateway_stopped.py`，都正确报
`still_running` —— 门禁是好的，是它选错了解释器。

**已写进三个 worker 的人格**：跑命令用 `<PROJECT_ROOT>\.venv\Scripts\python.exe`，
不许裸 `python`；实测结论必须写清用的哪个解释器。

**这条恰恰证明了 auditor 角色的价值**：worker 会自信地报告假发现，**必须有独立核对**。
