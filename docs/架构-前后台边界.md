# 前后台边界 —— 怀恩到底用了什么

> 用户 2026-10-30 原话：*"整体的记忆，工具调用等都是单独做的还是用的 hermes？怎么做的区分？hermes 里是否能看到？"*
> 这份文档就是逐条回答。

## 一句话结论

**没有另造任何一套。** 模型、工具、记忆机制、会话库、看板、cron —— 全部是 Hermes 原生的。
怀恩这个项目本身只做了三件事：**一个输入框 + 一个显示区 + 一层进程桥接**。

---

## 逐项对照表

| 能力 | 用的是什么 | 是不是另做的 | 在 Hermes 里能看到吗 | 怎么区分 |
|---|---|---|---|---|
| **模型推理** | Hermes 的 agent（MiniMax-M3 / minimax-cn 端点） | ❌ 用的 Hermes | ✅ 会话标题、回复全文都在 `state.db` | 前台只是 `hermes chat` 的客户端 |
| **工具调用** | Hermes 的**全套**内置工具（web/terminal/file/code_execution/memory/skills/cronjob/delegation/vision/tts…） | ❌ 用的 Hermes | ✅ 工具调用与结果都在会话消息里 | 由 Hermes agent 自己决定调什么，前台不参与决策 |
| **长期记忆** | Hermes 的 memory 机制（`memories/MEMORY.md` + `USER.md`） | ❌ 用的 Hermes 的机制 | ✅ 就是 Hermes 自己的记忆文件 | 前台 `huaien` profile 一份，后台 `default` 一份，**脚本做条目级双向补齐** |
| **会话历史** | Hermes 的 `state.db` | ❌ 用的 Hermes | ✅ `hermes -p huaien sessions list` | 前台会话 id 以 `local-` 开头，存在 huaien profile 的库里 |
| **任务看板** | Hermes 的 kanban | ❌ 用的 Hermes | ✅ `hermes kanban` / 官方 dashboard 页 | 前台**不显示**；只有你主动问才说 |
| **定时任务** | Hermes 的 cron | ❌ 用的 Hermes | ✅ `hermes cron list` | 同上 |
| **凭据（API key）** | Hermes 自己的凭据库 | ❌ **前台完全不碰** | ✅ 只在 Hermes 侧 | `huaien/bridge.py` 里搜不到任何 key 相关代码 |
| **界面渲染** | Tkinter | ✅ 这部分是本项目自己写的 | — | `huaien/app.py` + `theme.py` |
| **进程桥接** | 调 `hermes chat --format stream-json` | ✅ 本项目自己写的 | — | `huaien/bridge.py` |

## 三个最容易搞混的点

### 1. 前台和后台是不是"同一个人"？

**人格上是两个，记忆上是同一个。**

- **人格分离**：前台跑在独立 profile `huaien` 上，它的 `SOUL.md` 写的是
  "话不多、答完就停、不用 Markdown、不写自检行"。
  后台（default profile）的人格契约是"结论先行 + H2 分段 + 格式自检" ——
  那一套拿到前台会很吵，跟你要的"极简管家"冲突。
- **记忆共享**：`huaien` profile 最初是**克隆自 default** 的，两边的
  `MEMORY.md` / `USER.md` 内容和结构完全一样。但克隆之后就是两份独立文件，会分叉。
  → `scripts/sync_memory.py` 做**条目级双向补齐**（只补不删），看门狗每次跑都同步一次。

  **为什么不能直接共用一个 profile？**
  Hermes 没有"换人格但共享记忆"的开关。`hermes chat --ignore-rules` 官方说明是
  *"Skip auto-injection of AGENTS.md, SOUL.md, .cursorrules, memory, and preloaded skills"*
  —— 它会把 memory 一起跳过，等于把记忆也丢了。

### 2. 前台说的话，后台（我）知道吗？

**现在知道。** 同步脚本在跑，两边条目实时对齐。

```
hermes -p huaien sessions list     # 看前台所有对话
hermes -p default sessions list    # 看后台对话
```

### 3. 前台会不会把后台的脏东西露出来？

**不会。** 三重保障：

1. `huaien` profile 的 `SOUL.md` 明令：不展示任务、卡片、日志、看板，不提"我在后台做了"。
2. 前台 UI **根本没有**任务卡/日志/进度的渲染代码 —— 只有一个输入框和一个文本区。
3. 桥接层只取 `stream-json` 里的 `text` 事件，`tool_call` / `thinking` 之类的事件**根本不转发**。

## 数据流向

```
  你
  │  打字 (原生 Tk Text → Windows IME)
  ▼
┌──────────────────────────────┐
│  huaien/app.py   (Tkinter)   │  ← 本项目: 只负责显示和输入
│  huaien/bridge.py            │  ← 本项目: 起子进程、解析 stream-json
└──────────────┬───────────────┘
               │  hermes -p huaien chat -q "..." --format stream-json
               ▼
┌──────────────────────────────┐
│  Hermes Agent (huaien profile)│  ← Hermes 原生: 模型 + 工具 + 记忆 + 会话
└──────────────┬───────────────┘
               │
               ├──► 会话写进 huaien profile 的 state.db
               ├──► 记忆写进 huaien profile 的 memories/
               ├──► 工具调用留在 Hermes 里 (前台看不到)
               └──► 看板 / cron / 飞书 —— 需要时由 Hermes 自己调度

  scripts/sync_memory.py  ← 定期把 huaien 和 default 的记忆条目对齐
```

## 想自己验证

```bash
# 前台所有会话都在 Hermes 里
hermes -p huaien sessions list

# 看前台的记忆文件 (和后台同源)
type "%HERMES_HOME%\profiles\huaien\memories\MEMORY.md"

# 记忆是否同步 (差 0 条 = 已对齐)
python scripts/sync_memory.py --check

# 前台有没有藏起凭据 (应该搜不到)
grep -rniE "api[_-]?key|password|secret" huaien/

# 看门狗三件事的状态
python scripts/watchdog.py --status
```

## 一句话总结

> **前台是壳，Hermes 是脑。**
> 壳只做三件事：给你一个能打字的框、把 Hermes 的话显示出来、把键盘上的回车变成一次 `hermes chat`。
> 除此之外的一切（模型、工具、记忆、会话、看板、cron、凭据）**全是 Hermes 原生的**，
> 你在 Hermes 里都能看到，前台只是不主动展示。
