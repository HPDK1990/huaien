## 二、方案设计

### 目标（用户原话翻译成可验收项）

| # | 目标 | 验收标准 |
|---|---|---|
| G1 | 前台**具备完成 Hermes 工作能力** | 前台发一句"去干某件真事"，agent 真的调工具、真的产出结果、结果回到前台 |
| G2 | 前台**能拆分任务** | 前台发一句长任务，agent 真的建看板卡并回报编号 |
| G3 | 前台**能看任务和汇报** | 前台问"任务到哪了"，得到人话汇报；主动汇报能推到飞书 |
| G4 | **前台真实操作测试** | 测试器驱动真实窗口（点/打字/回车），断言基于**可见状态**而非内部变量 |
| G5 | **外部对接端口** | 飞书通道实测可用；手机端有一条路能落地 |
| G6 | **多格式输入输出** | agent 产出的文件/图片能在前台看到并打开 |
| G7 | **新版本文件夹 + 封存** | `versions/V0.3.0/` + git tag |

### 关键设计决策

**D1 — 不改 Hermes 源码，只用它的原生能力。**
`huaien` profile 已带 kanban/delegate/todo 工具，能力是现成的，缺的是**前端呈现**和**人格授权**。
改 Hermes 源码会被上游覆盖，且违反"用 Hermes 原生"的前提。

**D2 — 进度反馈走"agent 先应一声" + "前端计时" + "前端轮询看板"三条腿。**
`stream-json` 没有工具事件，所以不能等 Hermes 推进度。三条腿都不需要改 Hermes：
- agent 先回一句"我去办 X" → 立刻有反馈（改 `huaien/SOUL.md`）
- 前台计时 → 超过 8 秒显示"还在想（N 秒）"
- 前台轮询 kanban → 有卡在跑就显示"进行中"

**D3 — 结构化标记而不是解析自由文本。**
让 agent 用 `[[FILE:路径]]` / `[[IMG:路径]]` 标注产物，前台解析成卡片。
比"猜哪行是路径"可靠，且 agent 一行指令就能学会。

**D4 — 测试走 UI 事件层，不走函数调用层。**
用户明确"不要后台测"。测试器用 `event_generate` 发真实鼠标/键盘事件，
断言只看：canvas item 的文字、entry 的内容、截图的像素分布。

## 三、批判性审核（自己挑刺）

| # | 质疑 | 结论 |
|---|---|---|
| C1 | "给 huaien 改 SOUL.md 让它先回一声" —— **破坏极简**？用户要"话不多的管家"，加一句"我去办"算不算话多？ | **接受，但限死**：只在**长任务**（预计 >1 分钟）时先应一声；普通问答直接答。短任务多一句就是噪音。 |
| C2 | 前台轮询 kanban —— 前台是**独立 profile**，能看到 default 的卡吗？ | **能**。`hermes kanban list` 读的是**共享的 kanban 库**（`hermes/kanban`），不是 profile 私有。已实测：9 张卡可见。 |
| C3 | 前台显示"文件卡片"会不会破坏极简？ | **接受，但卡片要极简**：一行灰字 + 文件名 + 双击打开，不加图标堆。 |
| C4 | 飞书通道**可能实际不通**（我在后台跑，没法验证用户那边能不能收到） | **必须诚实**：我只能验证"gateway 已连接"和"发出去不报错"，**收端必须用户自己在飞书发一条来确认**。这是硬边界。 |
| C5 | 公网 IP 到底能不能直连手机？ | **本地无法证实**。STUN 被封，且本地自测是 hairpin（会低报失败）。给用户一个**一键外部验证脚本**，用手机流量测。**不能拍脑袋说"行"**。 |
| C6 | 手机 App —— 用户说"如果能写个手机软件最好了" | **真写 App 不现实**（要签名/上架/应用商店）。**可行替代是 PWA**：同一个 HTML 界面，手机加到主屏跟原生 App 一样，且局域网可直连。这是"能落地的手机软件"。 |
| C7 | 输入图片要不要现在做？ | **降级**：Tk 的 Text 粘贴图片需要自己读 DIB 转 PNG，Windows 剪贴板格式杂。V0.3 先支持**文字 + 路径引用**，图片粘贴作为已知限制记下来。**不硬凑**。 |
| C8 | 加这么多功能，会不会把前台变成"后台看板"？ | **红线**：前台永远只有一个输入框 + 一段对话。任务状态最多**一行**灰字，不做列表、不做卡片墙。用户明确"不想看后台跑的程序和东西"。 |

## 五、已知限制（诚实记录，不粉饰）

1. **飞书收端未验证** —— 需要用户自己在飞书发一条消息确认。
2. **公网可达性未证实** —— STUN 被封，只能靠外部网络实测。
3. **图片粘贴不支持**（V0.3），文字 + 路径支持。
4. **窗口级任务进度只有一行**，做不了实时看板 —— 这是极简原则的主动取舍，不是能力缺失。
